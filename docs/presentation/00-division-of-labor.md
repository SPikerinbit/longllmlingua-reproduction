## 整合

1. 每人只在自己的分支上改自己的 `members/memberN/` 和自己负责的报告节。共享模板的配色不要分叉。
2. 成员四从四条分支取出 `members/` 下的定稿，合进一份幻灯片。P1/P2/P7 用成员一的 `slides-P1-P2-P7.pptx`，不要用建议句覆盖。
3. 报告用成员一的初稿当第 1–3 节和第 8 节的底子，贴上成员二、三、四的节，导出 PDF 后数正文页。超过 6 页先砍案例叙述，不砍表。
4. `results/` 按本文件的总表复制轻量文件，并附组内大文件的路径和 sha256。不要把 API key、权重、虚拟环境打进 zip。
5. 交叉核验：成员二对成员一的问题 ID 和“答案不进提示”；成员一对成员二的参数表是否和 `stage2-parameter-map.md` 一致；成员四对成员三的主表；成员三对成员四没有把 83.2 和 82.6 写成一次实验。
6. 不创建 stage-ready 标签，不代替别人合并 PR。
