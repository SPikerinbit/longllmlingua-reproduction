摘要     针对长上下文问答中的冗余与位置偏置，本文整理并核验 G14 已有的 LongLLMLingua 复现记录。
CUDA pilot 100 题上，2×压缩 EM 为 83.2%，原始提示为 84.6%；按题配对的差值 95%区间为[−6.2,
+3.0]个百分点。独立 NPU 实验表明问题感知文档筛选作用较大，但本批次未获得端到端加速。本文仅作既
有实验汇编与离线核验，不声称重新推理。

1 问题与复现范围
LongLLMLingua[1]通过提高与问题相关的信息密度、调整信息位置并恢复输出子序列，缓解长提示
的成本与性能问题。本文检验三个问题：同一问答设置下能否在 2×/4×压缩后保留准确率；哪些模块
贡献较大；输入缩短是否转化为整条流水线加速。

范围限定为 Natural Questions 的 20 文档多文档问答版本[2,3]与固定 pilot 100 题、五个 gold 位
置；不覆盖原论文全部基准、训练或 GPT-3.5 绝对分数。问答模型替换为 deepseek-flash，因此属于
方法级而非逐数值复现。500 题仅有清单，不作为已完成结果。

2 方法与实现差异




  图 1 LongLLMLingua 原方法框架。来源：Jiang 等[1]，arXiv:2310.06839v2，图 2（原图截取，非本组实验图）。

粗粒度阶段以文档条件下的问题及 restrict 后缀的困惑度刻画相关性；细粒度阶段利用问题感知对比困

主比较关闭文档重排序，以保留五位置干预；重排序另列消融。固定实现中的 k=2 映射在当前路径无效，
τ_ins=0.85 与 τ_que=0.9 预压缩未实现；动态比率 0.3 按排名线性分配，不能宣称与论文控制完全等价
[5]。

3 数据、实现设置与公平性

3.1 输入与版本固定

数据总体为 2655 题。先按稳定 ID 排序，再用 seed=42 打乱，按嵌套前缀取得 smoke 20 题、pilot
100 题和 main 500 题。每题 20 篇文档，gold 置于 1、5、10、15、20（从 1 计数）。一“槽”指题目
×位置×方法，不是独立问题。输入仅含问题与文档 ID、标题、正文；参考答案、gold 标记和位置元
数据不进入 BM25 或问答提示[6]。

 项目            实际设置与来源

               LLMLingua 与 LongLLMLingua 共用 LLaMA-2-7B-Chat 镜像权重；fp16、eager，迭代段长
 压缩器
               200

 问答 API        deepseek-flash，非思考，temperature=0，max_tokens=512；历史真实记录保持不变

 计数与 BM25      DeepSeek 固定分词器；BM25 k1=1.5、b=0.75，unicode-word-lower-v1

 代码锁定          压缩库、数据模板与指标锁定提交；完整 SHA 见[9,10]，权重 revision 见附录 A

 实际批次          阶段三为 CUDA（仅 cuda:0，型号未登记）；阶段四为 Ascend910B4，不能合并硬件记录

3.2 指标、配对区间与预算边界

主指标沿用首行 best_subspan_em：先取模型回答第一行，再按上游规范化规则检查参考答案子串。
它不是语义正确性判定，否定句提及答案也可能得 1 分。统计先在每题内平均五位置，再计算方法与
original 的题内差值；以题目为单位配对 bootstrap 2000 次，seed=42，保留同题全部位置，报告
95%区间[7]。不能把 500 槽当作 500 道独立题。

所有方法共享题单、可见输入、模板、问答设置与计数口径。硬预算目标为⌊原始完整提示本地 token
数/目标倍率⌋；压缩器最多 3 轮收紧预算，保留超标槽而不删失。库内 context_budget=“+100”是
软余量，不是最终合格标准。恢复只作用于回答，且采用 DeepSeek 分词器，区别于论文恢复粒度
[5]。

本地预算仅计提示文本，不含 API 聊天封装；阶段一 300 槽的 API 输入均比本地多 4 token，不能将
文本长度直接当账单。压缩率均值是逐槽比值的平均，不等于 API 输入总量之比。temperature=0 和
返回 fingerprint 亦不足以证明不可变模型快照。

5 独立 NPU 消融与效率

5.1 单因素消融

阶段四 run a9d2295195adde90484d 基于 pilot 100 题、五位置，既有推理记录 3500 槽。参照是同机
Long 2×的 82.6%，不是 CUDA 的 83.2%。表 2 中“无恢复”由已有恢复前得分离线派生，不额外计
作 500 次推理[8]。

 方法/改动                                   EM (%)               Δ (pp)   95% CI (pp)

 Original                                84.6                 +2.0     [-2.2, +7.0]

 Long 2×完整                               82.6                 +0.0     参照

 无问题感知粗粒度                                45.0                 -37.6    [-47.2, -28.4]

 无问题感知细粒度                                81.2                 -1.4     [-4.2, +1.2]

 无恢复（离线派生）                               83.2                 +0.6     [+0.0, +1.6]

“无粗粒度”具体是将 rank_method 改为 llmlingua，仍保留文档过滤，并非禁用整个筛选过程；其
−37.6pp 支持问题感知排序在本设置的重要性。去动态预算下降 4.6pp。细粒度与 restrict 的区间跨
0，证据不足以稳定排序小幅效果；主比较原本关闭重排序，此处为额外打开而非再次移除。

关闭恢复的点估计反而高 0.6pp，区间[0.0, +1.6]包含边界 0；已有 3 条恢复由对变错记录，集中于 2
题。恢复不是单调有益模块，不能以原论文叙述替代本批次负面证据。

7 局限、代码与 AI 辅助披露
结论受单一数据集、100 题、五位置及问答模型替代限制。硬预算、恢复分词器与无效 k 映射偏离论
文；API 版本非不可变快照。未预注册等效界值，消融区间未作多重比较校正，小差异不作稳健优劣结
论。

CUDA 型号、阶段四 CANN 及阶段二/三/四完整输出、压缩/问答缓存和校验和仍缺，不能独立重放全
部推理；阶段一 canonical 预测已核验。历史 tokenizers 0.21.0/0.21.4 与本机离线 0.22.1 分开，阶
段二 16.67 GB 与效率 16.428 GB 不合并。

代码依赖锁定版本的 LLMLingua 与 Lost in the Middle；本文档更新未改源码或原结果。AI 辅助仅
用于汇编、写作、图表与排版，不生成模型回答、压缩文本或案例。2026-11-21 初版所载 43 项为历史
回传，当时未在报告环境亲跑。同日 17:46:58–17:47:02（北京时间），本机完整 pytest 为 77/77、退
出 0，问答 API 调用 0；配齐公开 NQ 与固定分词器后，原 72 过/5 因缺资源失败已解决[12]。这是离线
代码/记录核验，不是重新推理 3500 槽，原分数未改。

受控 Cursor 回答仍缺、无新分数，不把对话当 DeepSeek API。代推进不冒充成员亲历，也未代勾自
检。占位资料包已生成，P 编号、四人登记信息与本人确认仍缺。50 秒离线验收实录已完成，但不等
同真人讲述计时、成员本人参与或新模型实验，不宣称课程满分。

8 结论
本次方法级证据支持 LongLLMLingua 较传统压缩基线保留更多问答性能，问题感知排序贡献突出；
但 2×未证成等效，4×有预算超标，且本批次无端到端加速。结论受批次、计数口径和缺失原始输出
限制。
